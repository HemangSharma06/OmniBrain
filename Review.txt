OmniBrain Project Review
========================
OmniBrain — Short Hinglish Review for Presentation
=================================================

Summary (1 line):
- OmniBrain ek multimodal RAG system hai jo documents, tables, aur images ko samajh ke user ke questions ka jawab deta hai.

Project Flow — Start to End (concise Hinglish):
- User login/register (frontend Streamlit).
- User uploads file ya seed question bhejta hai.
- Upload → temp save → background ingestion (PDF/docx/images → OCR, chunking, embeddings) → Qdrant (text/images) ya Postgres (tables).
- Query → `/query` backend → Router agent decide karega: SEARCH / VISION / SQL.
- Chosen agent se data milega (retrieval/sql/vision) → Synthesis agent sab kuch combine karke final answer bhejta hai.

What to emphasize (presentation bullets):
- Multimodal: text + image + table support.
- Agent-based routing: small, testable components (router, search, vision, sql, synthesis).
- Local-first prototype: Qdrant + Postgres, easy to run and extend.

Key Files & Why They Matter (short Hinglish, one-liners + interviewer Q/A):
- `app.py`: API entrypoint — handles `/upload` and `/query`.
  Q: "Kya `app.py` me routing hota hai?" A: "Haan — endpoints yahin, `query` LLM graph call karta hai."
- `frontend/streamlit/app.py`: Streamlit entry & login — user-facing start page.
  Q: "Auth state kaise restore hota hai?" A: "JWT query param or `st.session_state` se — `restore_auth_state()` use hota hai."
- `frontend/streamlit/components.py`: shared UI + auth + browser storage.
  Q: "Chat history kahan save hoti hai?" A: "Browser localStorage, user-scoped keys; logout clears current user keys."
- `frontend/streamlit/pages/2_Chat.py`: Chat UI — handles messages + calls `query_agent()`.
  Q: "New chat kaise create hota hai?" A: "New chat generates new `conversation-<id>` and resets `messages` (fix applied)."
- `frontend/streamlit/pages/5_Chat_History.py`: Shows saved conversations.
  Q: "History device-specific hai ya cloud?" A: "Device-specific (localStorage). Backend persistence is future work."
- `backend/graph/graph.py` & `backend/graph/nodes.py`: LangGraph workflow — defines agent nodes and transitions.
  Q: "Router ka decision kaise hota hai?" A: "LLM prompt-based decision; safe fallback rules in prompts."
- `backend/agents/*`: `routerAgent`, `searchAgent`, `visionAgent`, `sqlAgent`, `synthesisAgent` — each does focused work.
  Q: "Agar agent fail ho jaye to?" A: "Currently error bubbled; we can add retries/fallbacks later."
- `backend/ingestion/*`: chunking, PDF/docs/images ingestion — prepares data for embeddings.
  Q: "OCR kaun karta hai?" A: "EasyOCR / fitz used in ingestion pipelines."
- `backend/ingestion/VectorDB.py` & `backend/retrieval/*`: Qdrant integration and retriever.
  Q: "Image vs text vectors kaise handle hota hai?" A: "Text and images stored in separate Qdrant collections; CLIP used for images."
- `backend/vision/clip.py`: CLIP wrapper for image embeddings & basic image analysis.
  Q: "Vision agent image processing kaise karta hai?" A: "CLIP for embeddings, then LLM for interpretation."
- `backend/Database/db.py` + table ingestion: tabular uploads go to Postgres.
  Q: "SQL queries kaise generate hote hain?" A: "SQL prompt templates generate queries; results executed on Postgres."
- `backend/llm/prompt.py` + `backend/llm/llm.py`: all prompts and LLM wrappers.
  Q: "Hallucination kam kaise kiya?" A: "Prompts strongly instruct LLM to use only retrieved context and to format outputs strictly."

Gotchas / Limitations to Mention (short):
- Local Qdrant + Postgres = prototype-scale only.
- Browser localStorage history is device-specific and not secure for cross-device use.
- JWT in query params is convenient but not production-secure (use HttpOnly cookies in prod).

Suggested Next Steps (1-liners):
- Move chat history to backend for cross-device sync.
- Add refresh tokens + HttpOnly cookies for auth.
- Replace local Qdrant with managed vector DB for scale.

Quick interviewer-style checklist (say these quickly):
- "It’s multimodal, agent-based, and prototype-local; we balanced dev speed vs production hardening."
- "Main risk: ingestion and embedding cost on host — scale plan: move embeddings to managed service, queue uploads."
